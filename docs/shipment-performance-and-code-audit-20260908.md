# 自动标发性能修复与仓库代码审查

## 已确认原因

生产日志中的领星候选扫描通常为 32～57 秒。新物流查询此前还要先等待约 7～13 分钟的历史订单资格核验；异常页面与登录共用 300 秒等待预算，失败订单又会在同一长任务跨过 3 小时重试期限后被重新领取。一次任务实际查询 40 个 ALS，却执行了 139 次尝试。

单号搜索本来只需要读取数据库，但每次新建 Store 都重复迁移和历史修复。生产数据库副本中，一次搜索触发数百次查询和更新；三个并发请求分别耗时约 3.66、5.79、7.46 秒。客户端还可能被后台版本刷新不断替换正在进行的搜索。这些证据解释了固定开销和等待放大，但不等同于某次客户端输入到显示的完整计时。

## 本次修改

- 数据库升级到 v24，已有数据库升级前保留备份。启动时执行迁移和业务修复；当前版本的搜索、列表、统计走只读连接，并及时释放连接。高于源码版本的数据库拒绝降级读取。
- 单号包含筛选在 SQLite 中执行，保留 Unicode casefold、字面 `%` / `_`、拆单多命中和扫描错误行语义。完整资料只加载命中页，全局筛选项按队列版本缓存。未将包含搜索改为等值搜索。
- 队列版本由订单、物流、ERP、重新标发、扫描错误、旧邮件预览和商品身份资料的实际写入推动；无关客户通知写入不再使订单搜索缓存失效。复核锁和活动任务仍独立参与投影、筛选和版本判定。
- 当前搜索期间的后台更新合并到一次后续刷新；新输入继续采用最新请求优先。显示“正在搜索订单”，保留已经绘制的结果；最多预取一个相邻页。
- 普通物流固定本轮目标，并在原子领取条件中排除同一个 run_id 已尝试的订单。未来到期重试留给下一任务，浏览器恢复仍至多一次。
- 页面导航和就绪等待共用默认 30 秒预算；登录/验证单独保留 300 秒预算，登录结束后重新给页面 30 秒。使用目标详情 URL 的 DOM 就绪条件，回退轮询间隔不超过 500 毫秒且不超过剩余预算。人工处理验证的时间独立计算。连续三次页面技术故障停止整批，未读取订单不消耗业务尝试次数。
- 普通查询成功后，客户端另起历史复查任务，排队优先级低于普通查询。已开始的浏览器操作不会被强行抢占。历史流程仍保留近 15 天覆盖和重新标发安全核验；客户端关闭后，由下次扫描重新安排到期检查。
- 历史资格检查成功后缓存 3 小时，失败后延后 15 分钟；订单版本、资格证据变化及检测到换号会使缓存失效。不符合资格的订单跳过 WMS；只读 API 最多两路并发，同一轮相同系统订单复用详情/WMS请求，包裹证据仍按精确身份分别核验。
- 历史账号失效也会停止整批，页面读取失败不再计为“未变化”。结果区分失败和跳过，并记录普通查询、历史复查耗时，以及历史 API 请求数和耗时。

## 隔离数据基准

Windows / Python 3.14，本机临时数据库，分别生成 600 / 5,000 条订单和 21,000 / 175,000 条审计事件；每类缓存查询 20 个样本，三个并发查询共 30 个样本。全部为服务端读取路径，未访问生产 ERP 或执行标发。

| 场景 | 600 条 | 5,000 条 |
|---|---:|---:|
| 完整单号搜索，首次全局筛选项缓存为空 | 29 ms | 186 ms |
| 完整单号搜索，缓存后 P95 | 4.2 ms | 6.4 ms |
| 包含搜索，缓存后 P95 | 27 ms | 45 ms |
| 无结果，缓存后 P95 | 3.0 ms | 4.2 ms |
| 第一页，缓存后 P95 | 26 ms | 185 ms |
| 三个并发单号查询 P95 | 8.3 ms | 13 ms |
| 后台持有未提交写事务时的单号搜索 | 4.1 ms | 5.4 ms |

5,000 条数据的首次包含搜索和第一页约 216 / 225 ms；全局状态排序仍需要轻量索引，列表继续增长时值得进一步优化。上述数字不能推导正式客户端必然达到同样速度，也不能与生产机器的旧基准直接计算倍数。发布后仍需测量网络、请求排队、Qt 绘制和真实阿里页面的 P50/P95。

## 全仓库冗余审查

以修改前 Git 跟踪的 327 个文件为范围：276 个 Python、13 个 PowerShell、5 个 Shell、2 个 CMD，另有工作流、打包入口、配置及文档。使用 AST 语法、全仓库引用检索、去除位置和文档字符串后的函数体比对，并核对 CLI、PyInstaller、Docker、部署脚本和兼容导出入口。生成目录和用户数据不在源码范围内。

初筛发现 19 个无引用私有函数，沿删除后的调用关系再找到 1 个旧暂停执行器，共删除 20 个私有函数。包括旧的暂停操作、废弃的界面排序/通知操作、端口检查和解析辅助函数；急停当前实现及相应测试保留。清除重复测试导入和确认无用的生产导入。

生产代码有 8 组完全相同的较长函数体，已合并：

| 位置 | 处理 |
|---|---|
| 定制订单/自动标发分页 | 共用查询、重试、导航和预取方法，保留各页面业务投影 |
| 两种 CLI 环境配置 | 共用宽松的旧格式读取器，公开函数名和密码字面语义保持不变 |
| 本机/协调端阿里收货地址 | 共用公开 API 地址适配器 |
| 七类产品文件夹异常 | 共用字段初始化，保留七种异常类型和产品规则 |

清理后按同样规则复扫，无无引用私有函数候选，也无跨生产代码的相同较长函数体；剩余 5 组位于测试中的独立桩/场景，保留以便各测试单独维护。

未使用导入初筛有 149 个候选，其中包含旧模块的公开兼容导出、Qt 可用性探测和测试导入，不能把这个数字当作可删除代码量。`pages/order_detail.py`、`pages/order_management.py`、`ui/controller.py` 等兼容入口经架构测试覆盖后保留。严格的桌面配置导入器与宽松 CLI 读取器语义不同，保留两个入口。

该审查覆盖全部跟踪源码，但静态规则不能证明不存在动态调用或语义相似的重复逻辑。较大的 Qt、队列和产品规则模块仍适合以后按职责继续拆分；本次未把“代码很长”作为删除依据。

## 验证及发布边界

已补充写事务期间只读搜索、跨重试时点去重、连续页面故障、独立登录预算、历史缓存失效、API并发上限、包含搜索兼容及界面刷新合并测试。现有换号、复核锁、急停、租约和产品业务测试共同回归；新增性能回归同时纳入服务器 Python 3.12 CI。

补充的可控时钟测试覆盖导航耗时 24 秒、29.8 秒和 30 秒：页面未就绪时不再追加完整的 30 秒等待。导航结束时发现登录页，仍使用独立登录预算；模拟三次“导航 24 秒后页面始终未就绪”，约 90 秒后停止，剩余订单不增加尝试次数。

本次不修改客户端版本、不发布 Release、不部署生产服务器、不替换已安装客户端。正式生效需要审核通过后按仓库发布流程执行，并通过客户端内置更新器升级。
