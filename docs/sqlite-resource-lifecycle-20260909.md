# SQLite 连接资源释放

协调心跳和队列查询等短操作离开 `with connection` 后，原有普通 SQLite
连接仍然开放，直到对象回收才释放相关资源。现在由底层
`lingxing_automation.storage.sqlite_connection` 统一提供连接生命周期：保留
SQLite 原有提交/回滚行为，在上下文退出及连接配置失败时关闭连接。

该模块只依赖标准库，不负责业务规则、数据库迁移、连接池或 UI。协调库、
定制订单库、发货库和客户通知库仍自行决定 PRAGMA 和事务边界。发货库的只读
连接继续使用只读 URI 和 `query_only`，并复用相同的关闭机制。

协调库备份、发货库备份、迁移前检查点和工作区完整性检查也关闭其所属连接。
备份目标无法打开时，已经打开的源连接同样关闭。已有阿里下单会话库的显式
关闭实现保留。逐处检查生产建连点及调用方后，未发现需要跨多个上下文复用
本次改动连接的生产路径。

## 隔离对照

基线源码为 `b157a22fe73a019ae49156023a2a2cd3dd1d4d88`。
`scripts/benchmark_sqlite_resources.py` 在独立子进程、临时合成数据库中，对
四个库执行 1000 轮、共 4000 次短查询连接；正常垃圾回收保持开启。测量进程
退出后才清理临时目录，避免用强制 GC 掩盖基线的句柄滞留。

Windows / Python 3.14.5 的首轮同条件测量：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 峰值工作集 | 68.71 MiB | 40.24 MiB |
| 采样到的进程句柄最大值 | 485 | 134 |
| 最后一次采样句柄数 | 255 | 134 |
| 查询循环耗时 | 2.1943 秒 | 4.0622 秒 |

立即关闭及重复打开连接增加了约 0.47 毫秒/次的平均开销。这是资源释放的
实测代价，不能据此声称所有查询变快。上述数据只代表该合成负载，不是生产
容器的常驻内存或可保证的释放量。

复现：

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_sqlite_resources.py --iterations 1000
```

通过 `--source-root` 指定同一基准脚本要测量的另一份源码检出，在新的子进程中
比较不同版本；不传入运行数据库或用户工作区。

## 验证范围

- 基线相关测试：594 项通过。
- 修复后事务、协调、定制订单、发货、客户通知、分页、审核投影、工作区和
  架构相关测试：636 项通过。
- 新增连接生命周期测试保留强引用，直接验证关闭，不依赖 GC。覆盖提交、
  约束冲突回滚、提前返回、提交时外键失败、建连配置失败、数据库忙、只读
  写入拒绝、备份失败、目标建连失败和并发事务。
- 底层模块的标准库依赖边界纳入架构测试，生命周期及核心数据库测试加入
  服务器 Python 3.12 CI；Windows 全量与打包检查沿用现有流程。

发布与部署仍按仓库受控流程执行；此改动不修改持久化业务状态定义、RPC 协议
或客户端安装目录。完整业务的服务器容量需要与中间层及真实浏览器组合验收。
